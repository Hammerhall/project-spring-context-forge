# ⚒️ Project Spring Context Forge

> **Кузня Spring №1 «Контекст и бины»: как Spring собирает объекты — на практике.**

> 💡 **Не заучивайте аннотации. Разберитесь, что делает контейнер.**

Откуда берётся бин? Почему дом получил тот же каталог, что и печать для зала, — или
почему не тот? Когда объект рождается и кто решает, какой из двух кандидатов
достанется сервису? В этой кузне каждая задача отвечает на один такой вопрос: вы
пишете конфигурацию, а закрытые тесты проверяют правило контейнера, а не «чтобы
работало на примере».

Без веба и без базы — только контейнер. Java 25, Spring Framework 7.

## 🏛 Аукционный дом

Первое место задач: каталог лотов, часы торгов, журнал аукциониста, шаг ставки,
служба ставок, участники с номерами табличек. Ядро дома лежит в проекте готовым —
пакет `io.hammerhall.springforge.auction`. Вы пишете только то, чему учит задача.

Деньги — в копейках (`Money`), лот — номер, название и стартовая цена (`Lot`),
сегодняшние торги — `SampleLots.today()`.

## ✈️ Аэропорт

Второе место задач — авиакомпания и её аэропорты. Данные настоящие: срез демобазы
«Авиаперевозки» компании Postgres Professional — 15 аэропортов, флот из 10 моделей,
схемы салонов; расстояние и время в пути считаются по формулам той же демобазы. Ядро —
пакет `io.hammerhall.springforge.airport`, срез — `DemoData`.

Данные — под лицензией MIT, © 2025 Postgres Professional,
[github.com/postgrespro/demodb](https://github.com/postgrespro/demodb). Текст лицензии
и что откуда взято — рядом с данными: `src/main/resources/io/hammerhall/springforge/airport/demodb/`.

## 🧭 Темы

| тема | что отрабатываем |
|---|---|
| 1. Бин и контекст | `@Bean`, компонент, конструктор, контекст как источник зависимостей |
| 2. Выбор кандидата | `@Primary`, `@Qualifier`, список и словарь бинов, `@Order` |
| 3. Конфигурация | `@Value`, `@ConfigurationProperties`, профили |
| 4. Время жизни | singleton и prototype, инициализация и уничтожение |
| 5. События | публикация, слушатели, порядок |
| 6. Внутри контейнера | постобработка бинов, прокси, полный и облегчённый `@Configuration` |
| 7. Автоконфигурация Boot | условия и стартер аукционного дома |

Тема 1 на аукционе открыта всем. Задачи выкладываются по мере готовности.

## 📐 Две оси сложности

**CODE** — механика: какие конструкции Spring нужны. **MIND** — мыслительная нагрузка:
задачи слоя мышления дают сломанную конфигурацию, и починить её можно, только поняв
правило. Слой кода — ступени Easy · Medium · Hard, слой мышления — Collapse и выше.

## 🚀 Начало работы

1. Сделайте Fork репозитория.
2. Клонируйте проект к себе.
3. Создайте ветку `solution`.
4. Откройте любую задачу и начните решать. Задачи независимы: каждая решается сама по себе,
   ответ одной не нужен для другой. По порядку — легче, но не обязательно.

Подробное описание процесса — [Forge Workflow](docs/forge-workflow.md).

## 🧩 Как устроена задача

Задача — один файл. Конфигурация и компоненты — вложенные статические классы в нём:
`Config`, `HallJournal` и другие. Закрытый тест поднимает контекст из вашего `Config`
и проверяет, какие бины есть, сколько их и кто в кого внедрён — по тождеству объектов.
Если задача о самом классе — о его конструкторе или зависимостях, — класс кладёт в контекст
проверка, так же, как это сделало бы сканирование компонентов; об этом сказано в условии.

Часы, шаг ставки и другое «окружение» даёт проверка: на ней свои часы и свои числа.
Решение, подогнанное под пример из условия, не пройдёт.

## 🧪 О тестах

`runTask()` рядом с задачей — **запуск, а не проверка**. Он поднимает контекст из вашего
`Config` и печатает, что вышло. Пока бина нет, `runTask()` красный: Spring скажет,
какого бина не нашёл, — это уже подсказка.

```
Это вывод, а не проверка. Проверить решение: ./hammerhall submit AucCode0001
```

Строгая проверка — закрытые тесты на платформе. Названия упавших подскажут, какое
правило не выполнено; самих проверок вы не увидите — иначе решать было бы нечего.

## ⚒️ Отправка решения

В корне проекта лежит `hammerhall` — клиент кузницы, он приезжает вместе с репозиторием.

```bash
./hammerhall login                 # первый раз: токен из личного кабинета
./hammerhall submit AucCode0001    # отправить решение
./hammerhall profile               # ваш профиль по осям
```

На Windows — то же через `hammerhall.bat`. Токен хранится в `.hammerhall/config`, этот
файл в `.gitignore` и в форк не уедет.
